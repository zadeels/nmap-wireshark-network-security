Nmap reported TCP port 80 as open because the Ubuntu VM accepted the TCP connection, responding to the initial SYN packet with SYN-ACK and completing the three-way handshake. In contrast, port 443 was reported as closed because Ubuntu responded to the connection attempt with RST-ACK, indicating that no service was accepting connections on that port. These responses were observed in Wireshark and explain the different port states identified by Nmap.

Following the implementation of UFW firewall restrictions, Wireshark captured repeated TCP SYN packets from the Windows host to the Ubuntu VM on port 80, without any corresponding SYN-ACK or RST responses. This behaviour was consistent with Nmap reporting the port as filtered. Compared with the initial capture, where the TCP handshake completed successfully, the results demonstrate that the firewall restrictions prevented inbound HTTP connections.
